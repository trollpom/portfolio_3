# Анна и Михаил — свадебное приглашение

Демонстрационный сайт для портфолио. Пара, дата 17 июля 2027 года и усадьба «Лесной берег» вымышлены. Все фотографии созданы ИИ. Светлая природная палитра вдохновлена [Wedding Invite](https://dribbble.com/shots/13150887-Wedding-Invite); композиция разработана самостоятельно.

## Публикация на Netlify

Эта версия подготовлена для **Next.js + Netlify**, а не для загрузки папки со статическими файлами.

1. Подключите `trollpom/portfolio_3` через **Import from Git**. Ветка — `main`.
2. Base directory — пустое поле (корень репозитория).
3. Build command — `pnpm run build`; Publish directory — `.next`. Значения уже закреплены в `netlify.toml` и имеют приоритет над настройками интерфейса.
4. Node.js 24 также указан в конфигурации. Netlify автоматически подключает актуальный адаптер OpenNext для Next.js.
5. Для старой неудачной публикации выберите **Deploys → Trigger deploy → Clear cache and deploy site**.

Не указывайте `public`, `dist` или корень как каталог публикации. Не загружайте ZIP исходников через Netlify Drop: он не выполняет сборку и не создаёт серверную часть. Не добавляйте общий redirect `/* /index.html 200`: маршруты страниц и API обслуживает адаптер Next.js.

Если ранее вручную включали старый плагин Next.js или `NETLIFY_NEXT_PLUGIN_SKIP`, уберите старую настройку: нужен стандартный актуальный адаптер Netlify.

## RSVP на Netlify

Ответы сохраняются в **Netlify Blobs**, site-wide store `wedding-rsvp`, ключи `responses/<UUID>.json`. Хранилище переживает новые деплои. При Git-деплое внешняя база, SQL-миграция и пользовательский API-ключ не требуются: серверный контекст предоставляет Netlify.

Организатор может смотреть и скачивать ответы в панели своего проекта **Data & Storage → Blobs → wedding-rsvp**. Общего публичного API со списком гостей нет. Клиент читает и удаляет только свой ответ по случайному ключу; сервер хранит SHA-256 ключа. Чтение строго согласованное, создание атомарное, повтор запроса не перезаписывает ответ. При сбое форма показывает ошибку, а не фиктивный успех.

Старые ответы из Cloudflare/Sites не переносятся автоматически: это разные хранилища. Файлы `drizzle/`, `.openai/` и `vite.config.ts` сохранены как исходные материалы прежней версии; **Netlify их не использует**. Рабочий маршрут `/api/rsvp` больше не импортирует `cloudflare:workers`.

## Возможности

- История пары, программа, площадка, дресс-код, FAQ и RSVP.
- Галерея из четырёх сгенерированных фотографий, клавиатура и диалоги.
- Обратный отсчёт и `public/wedding.ics`: 17.07.2027, 15:30–23:00, Москва (UTC+3).
- Иллюстративная схема вымышленной площадки; реального адреса нет.
- Восстановление собственного RSVP после перезагрузки и удаление ответа.
- Адаптивная вёрстка, локальные шрифты, анимации с учётом `prefers-reduced-motion`.

## Локальный запуск и проверки

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
pnpm start
```

Нужен Node.js 24. Обычный `next dev` показывает сайт, но без серверного контекста Netlify RSVP честно отвечает 503. Для локальной эмуляции Blobs используйте Netlify CLI (`netlify dev`) с привязанным проектом; не добавляйте реальные токены в репозиторий.

Тесты покрывают сохранение, повторы, восстановление через новый экземпляр адаптера, неверные ключи, конкурентное создание, удаление, валидацию и ошибки хранилища. Это проверки контракта API с тестовым хранилищем, не проверка аккаунта Netlify. Публикацию конкретного URL проверяйте отдельно после деплоя.

## Основные файлы

- `app/wedding.tsx`, `app/globals.css` — интерфейс и оформление.
- `app/api/rsvp/route.ts` — POST / GET / DELETE.
- `lib/rsvp-service.ts` — валидация и общий контракт RSVP.
- `lib/netlify-rsvp-database.ts` — адаптер Netlify Blobs.
- `netlify.toml`, `next.config.ts` — сборка и публикация.
- `public/` — изображения, шрифты, иконка и календарь.
- `image-prompts.md` — промпты фотографий.
