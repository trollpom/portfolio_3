# Анна и Михаил — свадебное приглашение

Полноценный демонстрационный сайт для портфолио. Пара, дата 17 июля 2027 года и усадьба «Лесной берег» вымышлены. Все фотографии созданы ИИ. В основе визуального направления — светлая природная палитра страницы-референса [Wedding Invite](https://dribbble.com/shots/13150887-Wedding-Invite), типографика с засечками, чёрно-белое фото и растительные линии. Макет референса целиком недоступен; композиция сайта разработана самостоятельно.

## Возможности

- Адаптивное приглашение, история пары, программа дня, площадка, дресс-код и ответы на вопросы.
- Четыре фотографии с просмотром в диалоге и перелистыванием кнопками или стрелками клавиатуры.
- Обратный отсчёт до события и корректный файл `public/wedding.ics` для календаря: 17.07.2027, 15:30–23:00, Москва (UTC+3).
- Иллюстративная схема вымышленной площадки. Реального адреса или маршрута нет.
- Настоящая форма RSVP: участие, количество гостей, спутники, меню, напитки и пожелания. Ответы сохраняются на сервере в Cloudflare D1.
- Повторные попытки отправки не создают дубликат. После перезагрузки на том же устройстве ответ загружается с сервера; его можно удалить и отправить новый.
- Каждый ответ защищён случайным ключом. В браузере хранятся только ID и ключ доступа; личные поля остаются в базе. Хэш ключа сохраняется на сервере, а просмотр и удаление требуют исходный ключ. Общего публичного списка гостей нет.
- Если запись в базу не удалась, форма показывает ошибку и не сообщает об успешном сохранении.
- Анимации учитывают `prefers-reduced-motion`. Шрифты локальные, внешние сервисы не нужны.

## Структура

- `app/wedding.tsx` — страницы приглашения и клиентские взаимодействия.
- `app/globals.css` — дизайн и адаптивные правила.
- `app/api/rsvp/route.ts` — POST/GET/DELETE для ответов.
- `lib/rsvp-service.ts` — валидация и работа с базой.
- `db/schema.ts`, `drizzle/` — схема и миграция таблицы `rsvps`.
- `public/images/`, `public/fonts/`, `public/wedding.ics` — изображения, шрифты и календарь.
- `image-prompts.md` — все промпты фотографий.

## Запуск

Нужен Node.js 24 или совместимая версия Node.js >=22.13.0. Установите зависимости командой `pnpm install`, затем используйте `pnpm dev` или `pnpm build`. Это проект с серверной частью: загрузка одних HTML-файлов на статический хостинг не обеспечивает сохранение RSVP.

Хостинг должен поддерживать Cloudflare Workers и D1 либо Sites. В `.openai/hosting.json` объявлен binding `DB`. Миграции `drizzle/` должны применяться перед обработкой заявок. При публикации через Sites это выполняется автоматически.

Для локальной базы после сборки примените SQL из `drizzle/` через Wrangler:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_cute_marvel_zombies.sql
```

Локальная и опубликованная базы различаются. Исходники не содержат настоящих ответов гостей, ключей доступа, credentials, node_modules или локального состояния базы. В передаваемом архиве не закрепляется идентификатор чужого экземпляра Site.

Ответы организатора доступны в таблице `rsvps` через инструменты базы опубликованного Site. Не публикуйте общий API чтения этой таблицы для гостей. Текущий экземпляр — приватная демоверсия для владельца.

## Проверка

Проверены TypeScript и сборка. Сервис RSVP проверен с настоящей SQLite-базой по сгенерированной миграции: запись и сохранность после повторного открытия, идемпотентность, отклонение неверных данных, нормализация отказа, обработка ошибок и чтение/удаление только по правильному ключу.

Визуальная проверка в браузере в текущей среде недоступна. Перед использованием для настоящей свадьбы замените демонстрационные имена, дату, адрес, схему и условия мероприятия.
